TRAVELOOP
Product Requirements Document
v1.0  ·  Hackathon Build  ·  Backend + Frontend Coordination
Personalized Travel Planning Made Easy
1. Product Overview
Traveloop is a full-stack, multi-platform travel planning application. Users can build multi-city itineraries, manage budgets, discover destinations and activities, collaborate with friends, and share plans publicly. This PRD is the single source of truth for both backend and frontend teams.
1.1 Vision
An end-to-end, personalized, intelligent, and collaborative platform that makes travel planning as exciting as the trip itself.
1.2 Key Goals
Allow users to create structured, day-wise itineraries across multiple cities
Auto-estimate budgets per trip segment and surface cost breakdowns
Enable activity and city discovery through search
Support community sharing and trip cloning
Provide admin analytics for platform monitoring
1.3 Platforms
Web (desktop-first, responsive to mobile)
Mobile-friendly layout required for all screens
1.4 Tech Assumptions
Backend: REST API (Node/Django/Laravel or equivalent)
Database: Relational (PostgreSQL recommended)
Auth: JWT-based sessions
File Storage: S3-compatible for profile photos / cover images
Frontend: Any SPA framework (React preferred based on wireframes)

7. Authentication & Security
7.1 JWT Flow
Token issued on /auth/login and /auth/register
Include in all protected requests: Authorization: Bearer <token>
Token expiry: 7 days (refresh with re-login or silent refresh endpoint)
Admin role checked via role field in decoded JWT payload
7.2 Route Guards (Frontend)

7.3 Password Policy
Minimum 8 characters
At least one uppercase, one lowercase, one number
Hashed with bcrypt (cost factor 12)
8. Non-Functional Requirements
Category
Requirement
Performance
All API responses < 500ms at p95. Itinerary and budget endpoints < 800ms.
Pagination
All list endpoints paginated. Default limit: 20. Max limit: 100.
Search
Debounce on frontend (300ms). Autocomplete endpoints must respond < 200ms.
File Uploads
Max 5MB per file. Resize avatars to 200×200px server-side.
Database
Use indexes on: user_id FK columns, trips.status, activities.city/type, notes.trip_id.
CORS
Allow origins: localhost:3000 (dev), production domain. Credentials: true.
Rate Limiting
Auth endpoints: 10 req/min per IP. General API: 200 req/min per user.
Logging
Log all 4xx/5xx with request ID, user ID, endpoint, timestamp.
Soft Deletes
Users and trips soft-deleted only. Hard delete only on admin explicit action.
Responsiveness
Frontend: mobile breakpoint at 768px. All screens must render on 375px width.
